# 无人超市 BI 插件 —— 图表规范

> 本文档 = **图表模式行为规范** + 架构约束。图表模式（在对话里做看板相关操作）**禁止修改插件代码**——发现插件问题记录并建议用户走创造模式（那边的规范见同目录 `PLUGIN.md`）。

---

## 0. 模式边界

- 图表模式**禁止修改插件代码/静态资源/数据文件**
- 发现插件 bug → 记录到 [CHART-ITERATION.md](./CHART-ITERATION.md)，建议用户走创造模式修复
- 例外目录（Forecast/、docs/ 进度日志）的改动不触发创造模式

---

## 1. 图表绘制全流程概述

```
用户需求
   ↓
【分类】L0/L1/L2/L3 判定（能否 SQL？要不要反复读？）
   ↓
【需求确认】绘制形式 + 图表样式推荐 + 筛选项推荐 + 算法判定
   ↓
【取数】get_meta（核对字段与白名单）
   ↓
【渲染】render_dashboard（schema；月度加 granularity:"month"）
   ↓
【预览】回复末尾附 dsh-ui 围栏（previewId），等待用户确认
   ↓
【保存】save_dashboard（filter_fields 传用户确认的筛选字段）
   ↓
【后续】用户可通过 ⋮ 菜单 modify_chart 修改定义
```

**输出优先级**（打开看板 10s 内出结果，平时不挂后台计算）：
1. 预计算结果表 / 物化视图（渲染 10~50ms，效率最高，持久化成本≈0）
2. 普通视图（渲染时付查询成本）
3. 实时端点（需缓存兜底，最后考虑）

## 2. 图表分类（L0-L3）

| 层级 | 含义 | 处理方式 |
|------|------|----------|
| **L0** 普通聚合 | chart_def 直接表达（单表 + 简单 filters/group_by/metrics） | 直接绘制 |
| **L1** 复杂查询 | 窗口函数 / 同环比 / 多表关联超出 join 能力 | 建议 PG 视图（SQL 归档 `sql/views/`），图表当普通表用；**维表关联与列间运算属图表原生能力**：join 单对象 `{table, left_key, right_key}` 或链式对象数组（最多 4 级按序合并，后级 left_key 可引用前级产出列，可选 `type:"left"|"inner"`，缺省 left=未命中事实行保留）+ group_by/metrics 表达式 + 相对时间筛选记号，不必建视图；kpi 同环比已原生：`compare {type:"prev_day"|"prev_period"}`（需时间列筛选，Host 自动对齐平移前一日/上一等长窗口取数），非 kpi 图或复杂窗口仍建议视图 |
| **L2** 离线算法 | 预测 / 分层 / 异常检测 | 结果表方案（`bi_plugin` schema），算法脚本按例外约定或登记新位置 |
| **L3** 在线参数化 | 实时推理端点（最后考虑） | 算法服务推理端点 |

**判定依据**：能否 SQL 表达？结果要不要反复读？要不要历史/回溯？

## 3. 需求确认清单（绘制前逐项过）

1. **绘制形式**：看板卡片（持久）还是会话围栏预览（一次性）？
2. **图表样式（自动推荐）**：
   - 时间序列 → line
   - 构成/占比 → pie 或堆叠柱
   - 排名对比 → bar
   - 单值指标 → kpi
   - 明细清单 → table
   - 二维密度/交叉分布 → heatmap（恰好 2 个 group_by 维度=XY 轴 + 1 指标）
   - 派生指标（客单价/单价等列间运算）→ metrics/group_by 写表达式即可，无需预建视图
   - 24x7 时段分布 → heatmap + group_by `["hour(order_create_time)","weekday(order_date)"]`（hour/minute/datediff/date_add 等日期函数可用于 group_by/metrics 表达式）
   - 一图多指标 → bar/line/area ≤4 个 metrics（第 2 条 series 自动挂第二 Y 轴，量纲悬殊组合免视图）、table ≤6 个聚合列、kpi 主值+对比值 ≤2 个；去重计数 `agg:"count_distinct"`（如 成交人数）；按聚合结果过滤（销售额>100 的品类）用 filters `{metric:"<alias>", op, value}`（having，聚合后执行），均无需预建视图
   - 数值格式化 → metrics 加 `format {unit:"千"|"万", decimals, prefix:"¥"}`（表格单元格与 kpi 数值按缩放+前缀+千分位显示，如 6698990 配 `{unit:"万",decimals:1,prefix:"¥"}` → ¥669.9万；原始值不变；柱/线数值轴仍显示原始刻度）
   - 枚举映射 → 图表加 `value_map {原始值:"显示名"}`（表格分组列与轴/饼图类目名显示层映射，如订单状态 0/1 → 待处理/已处理）
   - kpi 同环比 → kpi 加 `compare {type:"prev_day"|"prev_period"}`（需时间列筛选；metrics 恰 1 个；显示值附「较前一日/较上一周期 ±x.x%」）
   - 表格增强 → `rules [{column, op, value, style:{color,background}}]` 条件格式（注意：当前客户端表格不渲染单元格样式，规则仅透出数据）与 `showTotals:true` 数值列合计行
   - 按数据形状推荐后向用户确认
3. **筛选项（自动推荐）**：
   - 从 group_by 维度与既有 filterable 字段提炼候选（Host 只推荐「至少一个图表能消费」的字段；维表 join 列只有被某个图表真正取用时才会进入候选）
   - **看板级筛选绑定（R4 P2-3）**：缺省规则=筛选列出现在图表取数列中（group_by/metrics/filters/time_column）才应用到该图，图表用不到的筛选列自动跳过、不报错（join 维表列不会再打进未 join 的图表）；需要精确控制时图表可加 `filtersFrom:["列",...]` 显式声明接受的看板筛选字段（可少选收窄、也可声明本表有但未取的列放宽），`filtersFrom:[]` 表示该图不接受任何看板筛选
   - **销售类数据必须 filters order_status=1**
   - 趋势类未指明时间范围时默认近 30 天并主动确认；时间范围**优先写相对时间记号**（看板每次打开自动重算窗口）——`"today"`=今天、`"today-1"`=昨天、`"-30d"`/`"+7w"`/`"-1m"`=相对当前偏移（单位 d/w/m/y/h/min）、BETWEEN 数组逐项解析（如 `["today-29","today"]`）、对象形 `{relative:"-30d"}`；日期列用 today 系（解析为 `YYYY-MM-DD`），时间戳列用 now 系（`"now"`/`"now-2h"`，解析为完整时刻）；同一图表多个记号共用同一 now 快照
4. **算法判定**：按上方分类定 L 层级；L2 需确认调度方式与结果新鲜度预期

## 4. 绘制流程（详细步骤）

```
get_meta（核对字段与白名单）
  → render_dashboard（schema；月度汇总加 granularity:"month"）
  → 回复末尾附 dsh-ui 围栏（previewId）
  → 用户确认后 save_dashboard（filter_fields 传用户确认的筛选字段）
```

**关键注意事项**：
- `render_dashboard` 输出候选筛选字段（各图表 group_by 并集）并在 render 文本中引导模型向用户确认
- `save_dashboard` 新增 `filter_fields` 参数，每图存 `filterable = 确认字段 ∩ 该图维度`
- 月度数据必须加 `granularity:"month"`

## 5. 绘制注意事项（索引表）

| 条目 | 触发 | 处置 |
|---|---|---|
| 销售数据过滤 | 涉及订单/销售额 | filters 必带 order_status=1 |
| 预测数据 | 需求预测类图表 | 预测属 Power BI 体系（`Forecast/` + `forecast_results`），非本插件产物；插件如需预测图须按 L2 自建算法与结果表（`bi_plugin` schema） |
| 长标签/矮图 | 类目文字长 | 渲染层已内置 containLabel+truncate，无需手调 |
| 白名单 403 | 查询被拒 | 引导用户到设置页开放对应表 |
| L2 结果展示 | 算法结果表 | 卡片注明「数据截至 X」；算法失败展示最近成功批次 |
| 修改限制 | 用户要改图 | 定义走 modify_chart；布局是画布交互（拖拽/缩放），两者不混 |

## 6. 修改规范

- **可改（modify_chart）**：chart_def 全部字段——指标（含表达式计算字段）/维度（含表达式与 join 维表字段）/筛选/关联 join/图表类型/时间粒度/标题
- **不可改**：图表 id 与创建会话关联；其它视图的落位数据；结果表结构与算法脚本（属 L2 算法管理，走创造模式）；插件代码（走创造模式）
- **流程**：确认意图 → modify_chart 保存 → 渲染确认 → 数据问题与定义问题分开归因（数据实时查 8600，定义只管形状）

## 筛选交互规范（筛选卡片）

筛选弹层 = **字段下拉 + 条件项下拉 + 输入框（模糊搜索，选项列表同步过滤）**；时间字段特殊：**【开始时间】-【结束时间】双输入**（类型按该字段值的精度自动选 date / datetime-local），应用即 BETWEEN。

- **条件项**：等于 / 不等于 / 大于 / 小于 / 大于等于 / 小于等于；**可排序字段（数值/日期类）追加「介于」**——选中后输入框变为两个（起始/结束），时间两框可各自使用不同精度（如起始用日期、结束用日期时间，PG 按时间语义自动比较）；字段数据含空值时自动追加 **为空 / 不为空**（选后无需输入，直接应用）
- **统一卡片**：所有字段类型共用同一张筛选卡（宽度统一偏长），仅条件项集合与输入占位随字段类型变化
- **数据语义**：算子直接透传数据服务（= != > >= < <= BETWEEN IS_NULL IS_NOT_NULL），BETWEEN 值为 [起, 止] 数组
- **层级**：图表级（卡片 ⋮ 筛选，setChartFilter，仅作用于该卡，**所有图表都有**——字段候选 = 已登记筛选字段，缺省回退 chart_def 的 group_by + metrics 列）与视图级（视图栏胶囊，setViewFilter，作用于整个视图）同时生效，按 AND 叠加；视图级筛选是图表级筛选在整个视图上的整合入口
- **清除**：卡片内「清除筛选」只清当前字段；视图级把条件置空即移除；「应用/清除筛选」按钮文字居中
- **表格防溢出**：table 型图表在画布卡片内自动滚动（max-height 约束），不外溢遮挡其他卡片
